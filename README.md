

# GeoGuard Backend

GeoGuard is a **Spring Boot Java backend** for a location-aware security and tracking system. The backend is organized into separate modules for devices, locations, geofencing, alerts, advice, scheduling, security, exception handling, utilities, and WebSocket-based communication.

## 🚀 Tech Stack

- **Java**
- **Spring Boot**
- **Spring Web**
- **Spring Data JPA**
- **Spring Security**
- **WebSocket**
- **Maven**
- **REST APIs**
- Database: configure the database used by your deployment in `application.properties`

## 📁 Project Structure

```text
src/
└── main/
    ├── java/
    │   └── com.backend.geosentinel/
    │       ├── advice/       # Application-level advice and common response handling
    │       ├── alert/        # Alert-related functionality
    │       ├── config/       # Application and framework configuration
    │       ├── devices/      # Device management and device-related APIs
    │       ├── exception/    # Custom exceptions and exception handling
    │       ├── geofence/     # Geofence creation and location-boundary logic
    │       ├── locations/    # Location-related functionality
    │       ├── scheduler/    # Scheduled/background tasks
    │       ├── security/     # Authentication, authorization and security configuration
    │       ├── util/         # Utility/helper classes
    │       ├── websocket/    # Real-time communication using WebSocket
    │       └── GeosentinelApplication.java
    │
    └── resources/
        ├── static/            # Static resources
        ├── templates/         # Template files
        └── application.properties
```

> **Note:** The Java package in the current project is `com.backend.geosentinel`. The project/product name can be presented as **GeoGuard** without changing the existing Java package.

## ✨ Main Features

### 1. Device Management
The `devices` module handles device-related operations such as registering and managing tracking/security devices.

### 2. Location Management
The `locations` module is responsible for location-related operations and data used by the application.

### 3. Geofencing
The `geofence` module provides the foundation for defining geographical boundaries and handling location-based rules.

A typical geofence workflow is:

```text
Device Location
      ↓
Location Processing
      ↓
Geofence Check
      ↓
Inside / Outside Boundary
      ↓
Alert or Action
```

### 4. Alerts
The `alert` module handles security/location alerts generated by application events.

Examples can include:

- Geofence violations
- Device-related events
- Location-based alerts
- Other security notifications

### 5. Real-Time Communication
The `websocket` module enables real-time communication between the backend and connected clients.

This can be used for:

- Live location updates
- Real-time alerts
- Device status updates
- Event notifications

### 6. Scheduling
The `scheduler` module contains scheduled/background operations required by the application.

### 7. Security
The `security` module contains authentication and authorization related functionality.

Security responsibilities may include:

- User authentication
- Authorization
- Protected API endpoints
- Security configuration
- Token/session handling

### 8. Exception Handling
The `exception` module centralizes custom exceptions and error handling so that API errors can be returned consistently.

### 9. Advice & Utilities
The `advice` and `util` packages contain reusable application-level functionality and helper classes.

## ⚙️ Configuration

Application configuration is stored in:

```text
src/main/resources/application.properties
```

Configure the required values for your environment, such as:

```properties
# Server
server.port=8080

# Database
spring.datasource.url=YOUR_DATABASE_URL
spring.datasource.username=YOUR_DATABASE_USERNAME
spring.datasource.password=YOUR_DATABASE_PASSWORD

# JPA / Hibernate
spring.jpa.hibernate.ddl-auto=update
```

If the project uses authentication secrets, API keys, or external services, keep those values out of Git and provide them through environment variables or a local configuration file.

## 🔐 Security

GeoGuard is designed with a dedicated security layer so protected functionality can be separated from public APIs.

Recommended production practices:

- Never commit passwords or secrets.
- Use environment variables for sensitive configuration.
- Protect administrative endpoints.
- Validate incoming request data.
- Use HTTPS in production.
- Configure CORS according to the deployed frontend.
- Use strong authentication credentials/tokens.

## 🌐 WebSocket Communication

The `websocket` package provides the real-time communication layer.

A typical flow is:

```text
Tracking Device
      ↓
Backend
      ↓
WebSocket
      ↓
Connected Client
      ↓
Live Location / Alert Update
```

This is useful when the frontend needs to receive location or security events without repeatedly polling the REST API.

## 🗺️ Geofence Workflow

A basic geofence workflow can be represented as:

